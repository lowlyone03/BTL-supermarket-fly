6.1. Webhook hay long polling?

  PLAN_12 ghi telegramBotController.js webhook + env TELEGRAM_WEBHOOK_URL.

  Thực tế máy đồ án: Express HOST 0.0.0.0 cổng 3000, LAN, Windows Auth.
  Telegram không gọi được http://192.168.x.x:3000. Webhook bắt buộc HTTPS công khai.

  Nhóm đã có docs/HUONG_DAN_CLOUDFLARE_TUNNEL.md + 6_MO_DUONG_HAM_CLOUDFLARE.bat
  (link https://….trycloudflare.com đổi mỗi lần mở).

  Mặc định:

      TELEGRAM_WEBHOOK_URL có giá trị HTTPS
          → setWebhook lúc start; POST /api/telegram/webhook

      TELEGRAM_WEBHOOK_URL trống
          → Long polling trong process Node (dev / demo máy đơn, không cần tunnel)

      Telegram down / token trống
          → Log cảnh báo, KHÔNG crash POS

  Không chạy đồng thời webhook + polling.

  BẮT BUỘC khi chuyển sang long polling (kể cả lần đầu process start mà
  env không có webhook URL):

      Nếu trước đó bot đã setWebhook (máy khác, buổi test Cloudflare trước,
      hoặc restart đổi env): gọi deleteWebhook TRƯỚC KHI getUpdates.

      Lý do Bot API: khi webhook còn gắn, getUpdates trả về conflict /
      không nhận tin — triệu chứng “polling bật mà bot không nhận tin”.

      Thứ tự an toàn lúc start:
          1. Đọc env token; token trống → bỏ qua, POS chạy.
          2. Nếu có TELEGRAM_WEBHOOK_URL → setWebhook (kèm secret_token).
          3. Nếu KHÔNG có URL → deleteWebhook rồi mới vòng getUpdates.
          4. Không bật cả hai nhánh.

  Webhook Cloudflare tạm: mỗi buổi test phải setWebhook lại URL mới.
  Ghi vào checklist sprint.

  Thư viện: không bắt buộc node-telegram-bot-api. Khớp style hiện tại:
  fetch tới https://api.telegram.org/bot<token>/…
  Nếu thêm package, chỉ dùng lúc code, không nhét framework chat vào POS.
