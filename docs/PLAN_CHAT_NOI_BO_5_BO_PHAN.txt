S1. Ma trận kênh  (CHỐT MỚI — bỏ ma trận cứng “1 vai trò / 1 kênh”)

  #kho:        QL + Thủ kho + Mua hàng
  #mua-hàng:   QL + Mua hàng + Thủ kho
  #kế-toán:    QL + Kế toán
  #thu-ngân:   QL + Thu ngân
  #quản-lý:    chỉ QL
  #cửa-hàng:   tất cả

  Lý do: kho ↔ mua hàng cần nói đề nghị / giao thiếu / nhận hàng trên kênh
  bộ phận; không đẩy hết lên #cửa-hàng. Thu ngân vẫn KHÔNG vào #kế-toán
  (không lộ lương). Kế toán vẫn không vào #kho / #mua-hàng / #thu-ngân.

  Server enforce bằng ROOM_MATRIX (chatPolicy.js) + ThanhVienPhongChat.
  Không tin body client.

S2. CCCD — không 400 cứng mọi \b\d{12}\b

  Đây là guardrail đồ án. Chặn cứng mọi 12 số → false-positive (mã phiếu,
  mã tham chiếu, SĐT ghép…). KHÔNG giữ chặn cứng 12 số đứng riêng.

  - Cảnh báo mạnh / HTTP 400 chỉ khi có từ khóa CCCD|căn cước|CMND
    VÀ một cụm 12 chữ số trong cùng NoiDung.
  - 12 số đứng riêng: cảnh báo mềm (warning trong JSON và/hoặc banner UI),
    VẪN GỬI ĐƯỢC (200).
  - mật khẩu|password|otp|jwt|bearer|api[_-]?key: vẫn 400.

S3. Retention 90 ngày — MaTinCuoi là WATERMARK, không phải FK

  TinNhanDaDoc.MaTinCuoi = mốc đã đọc, KHÔNG FK bắt buộc tới tin còn sống.
  Cleanup: DELETE tin cũ (>90 ngày, trừ HeThong). Không xóa hàng DaDoc.
  Nếu watermark < MIN(MaTin) còn lại → vẫn đúng unread:
      COUNT TinNhan WHERE MaTin > MaTinCuoi AND DaXoa=0 AND MaNV_Gui<>me
  Ví dụ: xóa tin 1..80, user đang MaTinCuoi=50, tin sống từ 81 → mọi tin
  mới hơn 50 (tức toàn bộ tin còn lại của người khác) vẫn hiện chưa đọc.

S4. P5-MIN BỔ SUNG (review): realtime bắt buộc + đính tài liệu

  - SSE /api/chat/stream (hub riêng, không lẫn /notifications/stream).
    Fallback poll 3–4s nếu SSE rớt — không F5 / Ctrl+R.
  - Đính file trên tin: PDF, ảnh png/jpg/webp, tối đa 8MB, multer,
    lưu uploads/chat/ — KHÔNG serve public /uploads/chat (phải JWT +
    thành viên phòng qua GET /api/chat/files/:maTin).
  - Đính chứng từ hệ thống (loại + mã + snapshot + mở/in sẵn có) khi
    tra được bảng. Không OCR. Không bắt user xuất PDF tay nếu picker gọn.
  - UI: nút Chat + badge topbar (không lẫn #menuAssistant). Widget trái

3.1. Vì sao SSE /api/chat/stream, không nhét vào /notifications/stream

  notificationHub.flush() luôn gọi telegramNotify.onInboxChanged.

3.2. chatHub.js

  clients = Map<MaNV, Set<res>>
  subscribe(res, user): gắn res._flyMaNV, heartbeat ': keepalive'
  notifyChat({ maPhong, maTin, maNVGui, preview }) :
    SELECT MaNV FROM ThanhVienPhongChat WHERE MaPhong=@p
    chỉ writeEvent(res, 'chat', payload) cho member đang mở stream.
    Payload: { seq, at, maPhong, maTin } — KHÔNG gửi full NoiDung trên SSE
    (client REST GET tin mới). Tránh lộ tin trên log proxy.
  Không debounce chung mọi phòng (hoặc debounce 80ms theo maPhong).
  Không import telegramNotify / assistantService.

3.3. Polling fallback

  Client: nếu !inboxLive analog chatLive → setInterval 4000ms GET /api/chat/unread
  + nếu đang mở một phòng GET /api/chat/rooms/:id/messages?after=MaTin
  Tắt interval khi SSE ready trở lại.

4. SCHEMA SQL

Convention repo: tên bảng/cột tiếng Việt không dấu camel hoa chữ đầu,
NVARCHAR cho chữ, VARCHAR mã, DATETIME GETDATE(), IF OBJECT_ID IS NULL,
index IX_/UX_/PK_, FK tới NhanVien(MaNV).

Migration idempotent + ensureChatSchema.js (app start) giống TelegramDangKy
để máy thành viên quên chạy migrate vẫn có bảng.

4.1. PhongChat

  CREATE TABLE dbo.PhongChat (
      MaPhong      VARCHAR(40)  NOT NULL,          -- CH_CUAHANG / DM_NV_QL01_NV_KT01
      Khoa         VARCHAR(40)  NOT NULL,          -- cua-hang, dm:nv1:nv2
      TenPhong     NVARCHAR(100) NOT NULL,
      LoaiPhong    NVARCHAR(20)  NOT NULL,         -- KenhChung | KenhVaiTro | DM | Nhom
      MaVaiTro     INT           NULL,             -- kênh bộ phận; NULL = chung/DM
      MoTa         NVARCHAR(200) NULL,
      NgayTao      DATETIME      NOT NULL CONSTRAINT DF_PhongChat_NgayTao DEFAULT GETDATE(),
      TrangThai    NVARCHAR(20)  NOT NULL CONSTRAINT DF_PhongChat_TT DEFAULT N'DangMo',
      CONSTRAINT PK_PhongChat PRIMARY KEY (MaPhong),
      CONSTRAINT CK_PhongChat_Loai CHECK (LoaiPhong IN (N'KenhChung', N'KenhVaiTro', N'DM', N'Nhom')),
      CONSTRAINT CK_PhongChat_TT CHECK (TrangThai IN (N'DangMo', N'Dong')),
      CONSTRAINT FK_PhongChat_VaiTro FOREIGN KEY (MaVaiTro) REFERENCES dbo.VaiTro (MaVaiTro)
  );
  CREATE UNIQUE INDEX UX_PhongChat_Khoa ON dbo.PhongChat (Khoa);

4.2. ThanhVienPhongChat

  CREATE TABLE dbo.ThanhVienPhongChat (
      MaPhong      VARCHAR(40)  NOT NULL,
      MaNV         VARCHAR(20)  NOT NULL,
      NgayVao      DATETIME     NOT NULL CONSTRAINT DF_TVPC_NgayVao DEFAULT GETDATE(),
      AnKhoiPhong  BIT          NOT NULL CONSTRAINT DF_TVPC_An DEFAULT (0),  -- 1 = mất quyền
      CONSTRAINT PK_ThanhVienPhongChat PRIMARY KEY (MaPhong, MaNV),
      CONSTRAINT FK_TVPC_Phong FOREIGN KEY (MaPhong) REFERENCES dbo.PhongChat (MaPhong),
      CONSTRAINT FK_TVPC_NV    FOREIGN KEY (MaNV)    REFERENCES dbo.NhanVien (MaNV)
  );
  CREATE INDEX IX_TVPC_NV ON dbo.ThanhVienPhongChat (MaNV, AnKhoiPhong) INCLUDE (MaPhong);

4.3. TinNhan

  CREATE TABLE dbo.TinNhan (
      MaTin        BIGINT IDENTITY(1,1) NOT NULL,
      MaPhong      VARCHAR(40)   NOT NULL,
      MaNV_Gui     VARCHAR(20)   NOT NULL,
      TenNV_Gui    NVARCHAR(100) NOT NULL,         -- snapshot lúc gửi (đổi tên NV không sửa tin cũ)
      TenVaiTro_Gui NVARCHAR(50) NOT NULL,
      NoiDung      NVARCHAR(1000) NOT NULL,        -- cùng trần ThongBaoCuaHang.NoiDung
      LoaiTin      NVARCHAR(20)  NOT NULL CONSTRAINT DF_TinNhan_Loai DEFAULT N'VanBan',
      DuongDanFile NVARCHAR(260) NULL,             -- tên file trong uploads/chat/; không URL public
      TenFile      NVARCHAR(200) NULL,
      MimeFile     VARCHAR(80)   NULL,
      DungLuong    INT           NULL,
      LoaiChungTu  NVARCHAR(40)  NULL,             -- DeNghiMuaHang / DonMuaHang / PhieuXuat…
      MaChungTu    VARCHAR(40)   NULL,
      NgayGui      DATETIME      NOT NULL CONSTRAINT DF_TinNhan_NgayGui DEFAULT GETDATE(),
      DaXoa        BIT           NOT NULL CONSTRAINT DF_TinNhan_Xoa DEFAULT (0),
      CONSTRAINT PK_TinNhan PRIMARY KEY (MaTin),
      CONSTRAINT CK_TinNhan_Loai CHECK (LoaiTin IN (N'VanBan', N'HeThong', N'Anh', N'File', N'ChungTu')),
      CONSTRAINT FK_TinNhan_Phong FOREIGN KEY (MaPhong) REFERENCES dbo.PhongChat (MaPhong),
      CONSTRAINT FK_TinNhan_Gui   FOREIGN KEY (MaNV_Gui) REFERENCES dbo.NhanVien (MaNV)
  );
  CREATE INDEX IX_TinNhan_PhongNgay ON dbo.TinNhan (MaPhong, NgayGui DESC) INCLUDE (MaTin, DaXoa);
  CREATE INDEX IX_TinNhan_PhongTin  ON dbo.TinNhan (MaPhong, MaTin);

  P5-MIN: VanBan | HeThong | Anh | File | ChungTu.
  File thật nằm uploads/chat/, không base64 trong SQL, không static public.

4.4. TinNhanDaDoc

  CREATE TABLE dbo.TinNhanDaDoc (
      MaPhong      VARCHAR(40) NOT NULL,
      MaNV         VARCHAR(20) NOT NULL,
      MaTinCuoi    BIGINT      NOT NULL CONSTRAINT DF_TNDD_Tin DEFAULT (0),
      NgayDoc      DATETIME    NOT NULL CONSTRAINT DF_TNDD_Ngay DEFAULT GETDATE(),
      CONSTRAINT PK_TinNhanDaDoc PRIMARY KEY (MaPhong, MaNV),
      CONSTRAINT FK_TNDD_Phong FOREIGN KEY (MaPhong) REFERENCES dbo.PhongChat (MaPhong),
      CONSTRAINT FK_TNDD_NV    FOREIGN KEY (MaNV)    REFERENCES dbo.NhanVien (MaNV)
      -- KHÔNG có FK TinNhanDaDoc.MaTinCuoi → TinNhan(MaTin).
      -- MaTinCuoi là WATERMARK đã đọc, không phải khóa ngoại tới tin còn sống.
  );

  -- Unread một phòng (vẫn đúng sau cleanup 90 ngày, kể cả MaTinCuoi < MIN tin sống):
  Unread = COUNT TinNhan WHERE MaPhong AND MaTin > ISNULL(MaTinCuoi,0) AND DaXoa=0
           AND MaNV_Gui <> @me
  Badge topbar = SUM unread các phòng user còn quyền (AnKhoiPhong=0).

4.5. Seed 6 kênh  (trong ensure, không hard-code MaVaiTro số nếu có thể)

  INSERT PhongChat theo Khoa. MaVaiTro lấy từ VaiTro.TenVaiTro:
    quan-ly → N'Quản lý'
    kho → N'Thủ kho'
    mua-hang → N'Nhân viên mua hàng'
    ke-toan → N'Kế toán'
    thu-ngan → N'Thu ngân'
    cua-hang → MaVaiTro NULL

4.6. Retention 90 ngày

  Job trong ensureChatSchema mỗi lần start (và có thể gọi tay):
    -- Chỉ xóa tin. Không đụng TinNhanDaDoc (watermark sống độc lập).
    DELETE FROM TinNhan WHERE NgayGui < DATEADD(DAY, -90, GETDATE()) AND LoaiTin <> N'HeThong';
    -- Watermark nhỏ hơn MIN(MaTin) còn lại vẫn OK: unread = MaTin > MaTinCuoi.
  Không xóa PhongChat / thành viên / hàng DaDoc.
  Không lưu secret, OTP, JWT, ChatId Telegram trong 4 bảng này.
  Không FULLTEXT bắt buộc P5-MIN (search = P5-ĐỦ LIKE).

4.7. NhatKy  (audit số lượng, không dump nội dung)

  Khi gửi tin: logAudit action N'Gửi tin nội bộ', table N'TinNhan',

5.1. UC mới hay gộp UC01?  — KHUYÊN: UC01, không seed UC44/UC45 ở P5-MIN

  Telegram P1 đã chốt: bind OTP = UC01; UC44 chỉ nếu hội đồng bắt “mỗi tích hợp một UC”.
  Chat nội bộ cùng lý: mọi tài khoản login đã có UC01. ACL phòng ≠ catalog chức năng.

  Làm
    router.use(verifyToken);
    router.use(requirePermission('UC01'));
    Trong từng handler: assertMember(req.user, maPhong) dựa TenVaiTro + ThanhVienPhongChat
    + NhanVien.TrangThai + TaiKhoan.TrangThai. 403 tiếng Việt nếu không phải thành viên.

  Không làm
    Client gửi TenVaiTro / isAdmin: true.
    requireRole('Quản lý') cho mọi endpoint (TN phải chat được #thu-ngân và #cửa-hàng).

  Nếu hội đồng bắt UC riêng lúc báo cáo:
    UC45 — Chat nội bộ 5 bộ phận  (sau UC43; không chiếm UC44 Telegram).
    Seed 5 vai trò = UC45. Khi đó đổi requirePermission('UC45').
    Đừng dùng UC44 cho chat.


5.2. Endpoint  (prefix /api/chat, JSON tiếng Việt)

  GET    /stream
    SSE. verifyToken (query token như notifications). subscribe chatHub.
    event: ready { seq, at }
    event: chat  { seq, at, maPhong, maTin }
    event: room  { seq, at }     — membership / danh sách phòng đổi
    event: unread { seq, at }    — gợi ý refresh badge (thường kèm chat)
    Không event: inbox.

  GET    /unread
    { tongChuaDoc, phong: [{ maPhong, khoa, tenPhong, chuaDoc, tinCuoiAt }] }
    Chỉ phòng AnKhoiPhong=0.

  GET    /rooms
    Danh sách phòng user được vào, kèm chuaDoc, preview 80 ký tự tin cuối
    (cắt, escape phía client). Thứ tự: chuaDoc DESC, NgayGui tin cuối DESC.

  GET    /rooms/:maPhong/messages?before=&after=&limit=
    limit mặc định 50, max 100.
    403 nếu không phải thành viên.
    Không trả tin DaXoa=1 (hoặc trả LoaiTin HeThong “đã xóa” không nội dung).

  POST   /rooms/:maPhong/messages
    body { NoiDung } hoặc { LoaiChungTu, MaChungTu, NoiDung? }
    trim, max 1000. Cấm HTML (lưu text thuần; UI escapeHtml như dashboard).
    400 nếu rỗng (trừ khi đính chứng từ) / quá dài / CCCD+từ khóa (mục 8.2).
    12 số đứng riêng: 200 + canhBao (không 400).
    429 rate limit.
    403 không phải thành viên / phòng Dong.
    Insert + notifyChat. Trả { maTin, ngayGui, phong, canhBao? }.

  POST   /rooms/:maPhong/files
    multipart field TepChat (+ NoiDung chú thích). PDF/ảnh ≤ 8MB.
    400 loại sai / chữ ký file sai. 413 quá 8MB.

  GET    /files/:maTin
    JWT + thành viên phòng. inline preview. Không public /uploads/chat.

  GET    /vouchers?q=&loai=
    Picker chứng từ hệ thống (đúng quyền tra bảng). Không OCR.
  GET    /vouchers/:loai/:ma
    Snapshot xem/in (title, số, ngày, trạng thái) cho widget.

  POST   /rooms/:maPhong/read
    body { MaTinCuoi }  (bắt buộc = tin mới nhất user đã thấy)
    UPSERT TinNhanDaDoc. Không tin client MaTinCuoi > MAX(MaTin) phòng — kẹp trần.

  GET    /directory          — P5-ĐỦ DM: { MaNV, TenNV, TenVaiTro } đang làm, trừ chính mình
  POST   /rooms/dm           — P5-ĐỦ body { MaNV } tạo/lấy phòng DM
  GET    /rooms/:id/search   — P5-ĐỦ q min 3 ký tự, LIKE trong 90 ngày, cùng quyền phòng

  Mount trong app.js:
    app.use('/api/chat', chatRoutes);
    cạnh /api/notifications, TRƯỚC catch-all 404.
    Không mount dưới /api/assistant.


5.3. assertMember (bắt buộc mọi GET tin / POST)

  1. Token có MaNV, TenVaiTro.
  2. Phòng tồn tại, TrangThai=DangMo.
  3. EXISTS ThanhVienPhongChat (MaPhong, MaNV, AnKhoiPhong=0).
  4. (Phòng thủ) nếu LoaiPhong=KenhVaiTro: TenVaiTro là Quản lý HOẶC khớp VaiTro.MaVaiTro phòng.
     KenhChung: mọi role hợp lệ.
  Bước 4 chống hàng thành viên cấy tay sai. TN không bao giờ thấy CH_KETOAN dù client đoán URL.


5.4. Rate limit  (in-memory Map như assistantService.consumeRate, không Redis)

  Mỗi MaNV:
    20 tin / 60 giây  → 429 “Gửi chậm lại, tối đa 20 tin mỗi phút.”
    400 tin / ngày (Asia/Ho_Chi_Minh) → 429.
  SSE: 1 stream / MaNV; stream mới đóng stream cũ (tránh leak fd khi F5).
  Unread poll: không đếm vào hạn tin.


5.5. Lỗi chuẩn

  401  verifyToken — “Vui lòng đăng nhập!” / hết hạn (giữ nguyên middleware).
  403  không thành viên / tài khoản khóa.
  404  phòng không tồn tại (không tiết lộ phòng KT-only cho TN: trả 403 giống nhau
       để không dò MaPhong — khuyến nghị 403 cho cả hai).
  413  file vượt 8MB.
  429  rate.

      “Không gửi số CCCD/CMND trong chat.”
    - 12 số đứng riêng: không 400; gắn canhBao mềm, vẫn insert.
    - mật khẩu|password|otp|jwt|bearer|api[_-]?key → 400
      “Không gửi mật khẩu hay mã đăng nhập trong chat.”
  Không đọc cột NhanVien.CCCD để “xác nhận”.
